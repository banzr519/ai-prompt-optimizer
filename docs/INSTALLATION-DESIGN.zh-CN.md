# v2.4.0 安装体验与实施设计

[安装使用](INSTALL.zh-CN.md) · [验证记录](../evals/RESULTS-v2.4.0.md)

## 产品目标

普通用户把项目交给 Codex 并明确“安装并启用按需优化”，之后由固定程序完成文件与配置维护。
首版只承诺可在本地验证的安装流程。模型提示词可迁移、30 个文档入口、操作系统安装支持是三件事。

## 优先级与实际方案

| 优先级 | 实现 | 边界 |
| --- | --- | --- |
| P0 | 单一 Python 标准库核心；sh / PowerShell 薄启动器 | Python 3.9+；缺失时不声称零依赖 |
| P0 | 用户／项目范围、CODEX_HOME、覆盖文件优先级、托管规则 | 自写规则保留并提示审核；不保证每轮调用 |
| P0 | 检查、显式更新、关闭规则、备份卸载 | 不做后台静默更新，不强制覆盖个性化内容 |
| P0 | 固定提交下载、文件清单、暂存替换、异常回滚、事务日志 | 硬中断需要审核恢复；不承诺跨系统故障绝对原子性 |
| P1 | 一个构建器生成独立包和原生插件预览包 | 两个包的核心文件逐字节一致 |
| P1 | 独立 setup 技能复用配置核心 | 不创建第二份核心技能；原生客户端安装与自动引导待测 |
| 后续 | 原生插件分发入口、实际 Windows/Linux 集成验证、无 Python 的签名安装器 | 不在当前未验证时标成已支持或已发布 |

使用 Python 是为了避免 POSIX shell 与 PowerShell 分别实现文件哈希、状态迁移和回滚而出现差异。
通过 Codex 安装优先寻找已有运行时，不要求用户写代码；但本版确有 Python 依赖，不能宣传成任何机器均可一键完成。

## 文件与状态

`scripts/manage_install.py` 负责状态与事务；`install.sh` 和 `install.ps1` 只定位 Python 并传递参数。
`references/installation.md` 是 Codex 维护入口。常规提示词任务不加载安装流程。

安装状态保存版本、来源提交（在线来源）、文件摘要、托管规则的精确内容和备份位置。
这些本机路径／规则可能包含私人信息，仅存于 Codex 本地状态目录，不进入分发包或公共仓库。
已安装内容被改动时拒绝更新及删除，先让用户决定如何保留定制。接管旧 Git 副本时保存整个历史副本。

配置使用明确标记。移除配置只删除由安装器记录且未被改写的区块，不删除用户自行编写的同类偏好。
重复运行相同安装不重复追加，也不制造新的备份。宿主管理的插件只接管偏好，不接管文件更新。

## 生成与分发

本地化新增安装入口放在 `locales/catalog.json`，调用原生成器生成；新增维护文档为英／简中回退。
保留全部 30 个语言／地区入口和原有翻译覆盖说明。核心语言行为与模型验证范围不因安装变化而扩大。

构建器从同一份源码生成两种 ZIP，固定归档顺序、时间戳与权限，并输出 SHA256SUMS。
校验和用于发现内容变化，不是独立签名或发布者身份认证。

本版插件结构参考当前机器中 OpenAI 随附插件的 `.codex-plugin/plugin.json` 和 `skills` 布局。

## 发布门槛

- 临时目录测试覆盖首次、重复、升级、旧 Git 迁移、关闭、卸载、配置冲突及异常恢复。
- 不运行或改写故意带 Bug 的评测样例；历史试用不记作本次新测试。
- 生成文件无漂移，链接有效，包内不含 Git 历史、凭据、缓存或私有配置。
- 未实测平台与客户端能力在验证记录中明确标注，不用平台脚本存在代替跨平台验证。
- v2.4.0 公共发布另行执行，成功核验后才更新发布状态；本地构建不自动创建 Release 或标签。
