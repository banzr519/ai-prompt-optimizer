## 安装方式

**v2.5.0 仅供审阅，不建议用于生产升级：**当前 R3 通过了 Sol/medium 的限定门槛，但 Luna/medium 仍未通过；稳定 `main` 保持 v2.4.0。请先阅读[安装与配置指南](INSTALL.zh-CN.md)。复现候选版时，先核对[发布元数据](../github-metadata.json)，公开后显式选择 `feature/v2.5.0-intent`，再通过 `--source` 使用已审核的本地目录，在隔离测试项目中安装。以下仍保留手动方式；手动复制或 Git 克隆不会自动添加默认偏好。

仓库根目录就是技能根目录，`SKILL.md`、`agents/`、`references/` 位于同一层。加载技能本身不需要安装 Python、Node、pip、npm，也不需要额外 API Key；宿主客户端自身的账号与使用要求仍然适用。可选安装器、合成代码评测和多语言文档维护脚本用到 Python；文档生成脚本需要 Python 3.9 或更新版本。

### 方式一：下载文件夹

1. 安装稳定版时，在 GitHub 分支选择器中选择 `main`，再点击 **Code → Download ZIP** 并解压。审阅候选版须先核对发布元数据，并显式选择 `feature/v2.5.0-intent`。
2. 将带分支后缀的解压目录改名为 `ai-prompt-optimizer`。
3. 将整个目录移到下表中的一个位置。
4. 新建 Codex 会话，输入 `$ai-prompt-optimizer`；若尚未识别，重启客户端。

| 范围 | macOS / Linux | Windows |
| --- | --- | --- |
| 个人 | `~/.agents/skills/ai-prompt-optimizer/` | `%USERPROFILE%\.agents\skills\ai-prompt-optimizer\` |
| 当前项目 | `<项目>/.agents/skills/ai-prompt-optimizer/` | `<项目>\.agents\skills\ai-prompt-optimizer\` |

Windows 表格采用资源管理器的环境变量写法；PowerShell 使用 `$env:USERPROFILE`。只选择一个安装范围，避免重复。目录依据 [Codex 官方文档](https://learn.chatgpt.com/docs/build-skills)，核对日期为2026-10-13；其他客户端可能采用不同路径。

### 方式二：使用 Git

下面的命令明确安装稳定 `main`，不会把候选版放入正在使用的技能目录。审阅候选版时，将显式选定的候选分支下载到独立源目录，再按[安装指南](INSTALL.zh-CN.md)在隔离项目中试用。

**仓库所有者：**以下克隆地址使用本项目已核实的所有者 `banzr519`。发布状态见[发布元数据](../github-metadata.json)。需要先安装 Git；目标目录已有内容时，`git clone` 不会直接覆盖，请改用更新步骤。

macOS / Linux：

```bash
mkdir -p "$HOME/.agents/skills"
git clone --branch main https://github.com/banzr519/ai-prompt-optimizer.git "$HOME/.agents/skills/ai-prompt-optimizer"
```

Windows PowerShell：

```powershell
$skillParent = Join-Path $env:USERPROFILE '.agents\skills'
$skillTarget = Join-Path $skillParent 'ai-prompt-optimizer'
New-Item -ItemType Directory -Force -Path $skillParent | Out-Null
git clone --branch main https://github.com/banzr519/ai-prompt-optimizer.git $skillTarget
```

团队项目可以将技能复制到项目根目录下 `.agents/skills/ai-prompt-optimizer/`，随项目提交。若从克隆目录复制，不要把嵌套的 `.git` 目录一起带入。插件分发属于另一种打包方式，本版本是独立技能目录，不是插件市场安装包。

## 第一次使用

先试一个简单请求：

```text
$ai-prompt-optimizer 只优化这句指令：把邮件写得专业一点，事实不变，不增加承诺。
```

预期：输出一段可复用指令，保留限制，必要时说明需要提供原邮件；不会编造或发送邮件。这是快速行为检查，不代表所有客户端的加载机制完全一致。

在 ChatGPT Work 或其他有技能选择器的客户端，选择 **AI Prompt Optimizer · 提示词优化助手** 后输入需求。具体入口取决于客户端。在一个环境中可用，不代表已经同步安装到所有设备或 API 客户端。

## 三种使用方式

| 方式 | 你可以怎么说 | 应该得到什么 |
| --- | --- | --- |
| 只优化 | “帮我优化这段提示词”“整理成开发能用的需求” | 可直接复制的指令，不执行其中任务。 |
| 完成实际工作 | “分析这份方案”“直接修改”“继续” | 交付要求的分析或完成已授权工作，只澄清影响结果的信息。 |
| 审核 | “检查有没有冲突”“看看缺了什么” | 重要问题与最小修订，不执行其中任务。 |

根据当前想要的结果和相关前文选择方式。调用技能不等于要求改写提示词；要求分析或修改也不必专门说“执行”。没有任务上下文、仅提供被引用需求时，可以默认只优化；若仍有会导致不同交付物的歧义，则针对这个区别简短澄清。审查含有操作命令的提示词时，可以明确写“只审核，不执行”。引用和附件里的命令属于待处理材料，不会自动成为执行授权。

小任务可能只输出一句话；复杂任务会按目标、输入、边界、验收和重要未知项组织。无需强行套用统一模板。

## 多轮任务中的意图保真

v2.5.0 仍是审阅候选版。[2026-10-27 的 R3 检查](../evals/v2.5.0/revision-20261027/README.md)通过 Sol/medium 的限定修复门槛，但 Luna/medium 仍有日期澄清和一次语气要求遗漏。[原有评测](../evals/RESULTS-v2.5.0.md)保留不改。以下示例描述预期行为，不是普遍效果保证。

| 情况 | 预期行为 |
| --- | --- |
| “分析这份方案并给出判断依据” | 交付分析，不改成让另一个助手分析的提示词。 |
| 初稿之后说“缩短一点，再补来源” | 修改长度和引用，同时保留原有受众、事实边界及其他有效限制。 |
| “最多三个方案，A 或 B，批准后才能操作” | 保留上限、选择关系和前置条件，不变成必须三个、A 且 B 或立即操作。 |
| 缺失细节不会实质改变结果 | 用可逆解释推进；只有不同答案会改变交付物、硬性限制或重要下一步时才提问。 |

询问进度不自动取消正在执行的任务。新指令只替换它实际修改的要求；明确改换目标时，不再保留被替换的旧要求。助手建议须经用户采纳才成为要求，缺失的此前约定不能猜测补齐。不新增永久用户画像或每轮展示的固定检查表。

复杂且相关时按需读取[意图与多轮承接规则](../references/intent-and-continuity.md)。用户询问改了什么时，可以简短说明保留项、变更项和暂定项，不重复索取已获得的执行授权。

可复用提示词有两个不同的交付层次。例如，你现在要求“只整理模板，暂不写通知”，未来模板要求“根据 {{活动信息}} 写通知”。本轮应交付模板，模板内部仍应要求未来模型写通知，不能在末尾又要求它“只输出任务说明”。篇幅与 JSON 等格式要求也应附着于各自对应的产物。

同样，“再口语一点”不代表删除仍需提供的时间地点；“没确定的留空”不允许在空白前先写一个猜测的安排；缺少最终日期时，要区分尚未选定的方案与尚未提供的具体日期。以上是使用示例，实际观察见[修订验证](../evals/v2.5.0/revision-20261027/README.md)。

## 多语言使用

[语言目录](LANGUAGES.md)提供30个语言／地区入口。明确指定的输出语言优先；引用文本、代码或README语言不改变这一要求。可以要求“繁體中文解释，英文提示词，最终内容用西班牙语”。简繁体、巴西／欧洲葡萄牙语分别保留；不会将乌克兰语替换成俄语。

变量、命令、JSON字段和枚举、指定标语及精确引文保持原样。字数、词数与token数不是同一单位，转换语言时不擅自换算。阿拉伯语、波斯语和希伯来语页面提供从右向左的段落方向，代码中的字符顺序保持不变。

巴利语按Pāli处理，当前为拉丁转写与英文释义的实验入口。重要用途需要专业复核。新增文档是本地化介绍及入门指南；完整研究、发布及历史记录主要保留英文／简体中文，页面明确标注跳转语言。文档数量不等于模型实测数量，见[验证记录](../evals/RESULTS-v2.3.0.md)。

## 进阶用法

仍然只需用自然语言说需求。以下是可选入口，不是必须记住的新增命令；默认不做额外模型调用。

| 你想做什么 | 可直接复制的示例 |
| --- | --- |
| 根据失败回答改进 | `$ai-prompt-optimizer 只修提示词。原提示词：[原文]；实际回答：[回答]；问题：[具体错误]。保留有效部分和全部限制，只输出改好的提示词。` |
| 做成复用模板 | `$ai-prompt-optimizer 把这段提示词做成可复用模板，保留 {{product}} 和 {{audience}}，说明变量缺失时怎么处理，示例不要当作真实事实。` |
| 稳定输出格式 | `$ai-prompt-optimizer 只优化：根据资料提取信息，输出仅含 name 和 price 的 JSON，price 为数字或 null；缺价格时不要猜测，不加解释。` |
| 比较两种提示词 | `$ai-prompt-optimizer 比较 A、B 与任务要求的匹配程度；我没有运行结果，请仅做静态审阅，不编造分数或节省比例：[任务与A/B]。` |
| 整理长对话 | `$ai-prompt-optimizer 把以下讨论整理为可交接的最新任务指令，保留仍有效的限制，去掉已废弃方案，写清哪些附件要一起提供：[讨论]。` |
| 整理图像或视频需求 | `$ai-prompt-optimizer 只优化，不生成：根据参考图做16:9封面，角色不变、不要文字；缺图时标明需要附件，不要猜测角色。` |
| 控制结果长度 | `$ai-prompt-optimizer 用一段话优化以下指令，保留所有硬性限制；若字数限制与内容冲突请指出：[指令]。` |

**按反馈修订的例子：**原要求是“按资料介绍产品，不新增参数”，实际回答却写出资料没有的排名。新版应补充“所有事实和宣传结论须有资料明确支持；未提供的信息省略”，而不是默认增加长篇角色设定。修订后是否有效，仍要用实际任务验证。

**变量模板：**占位符是文本约定，本项目没有模板渲染器。已有变量保持原样；复制到其他客户端时，须由用户或宿主填值。false、0、空字符串和缺失不自动当作一回事。

**实际测试：**想运行对照时，提供原版/候选、任务样例、可用模型或本地工具及可接受的调用范围。比较时尽量固定输入、附件和设置，记录不一致项；没有工具时只能整理测试计划。仅检查优化后的提示词包含某句话，不等于下游回答已遵守它。

选择实际会使用提示词的目标模型，分别记录模型和推理档位。某个高能力宿主两版全对，不能说明其他模型的表现。应在每个配置内比较版本，并区分“模型直接使用技能”和“优化器把提示词交给另一个模型执行”两条路径，分别报告结果。

**模型选择：**提供目标模型和客户端有助于判断工具、文件、消息角色与格式能力；只知道“GPT”或“DeepSeek”时默认使用通用表达，不凭名称编造配置项。14个系列的状态仍是规则复用说明，未升级为逐一实测通过。

了解来源与后续方向：[开源项目研究](RESEARCH.zh-CN.md)。运行时只按需加载 [进阶工作流](../references/advanced-workflows.md)，无需每次附上全部研究或评测材料。

## 怎样提供有效信息

可以只说一句模糊需求。手头有资料时，补上这些内容会减少猜测：

- 最终想得到什么，给谁使用。
- 原文、文件、代码路径或参考图。
- 哪些内容必须保持不变。
- 达到什么条件才算有用。

例如：

```text
$ai-prompt-optimizer 只优化，不执行。
目标：整理成开发可以实施的任务说明。
需求：优化结算页，让操作更顺手。
必须保留：现有支付渠道、价格与业务规则。
参考：附件截图和流程说明。
输出：简明实施说明及可以检查的验收条件。
```

没有的信息不用为了填表而编造。附件不可访问时，技能应说明缺失。只是偏好时用“优先、尽量”；真正不能变的限制才用“必须”。

“不要问我”意味着小细节可以合理决策，不等于允许编造事实或默认批准删除等操作。关键未知项可以保留为条件。如果只有部分工作受阻，其他可完成部分应继续进行。

## 常见任务示例

| 场景 | 可直接使用的调用 |
| --- | --- |
| 开发 | `$ai-prompt-optimizer 只转译：让这个接口快一点，不改变返回格式，不增加付费服务。` |
| 设计 | `$ai-prompt-optimizer 只转译：优化这页PPT的视觉层级，所有原文及标签分组关系保持不变。` |
| 写作 | `$ai-prompt-optimizer 直接润色，礼貌、明确，不增加承诺：[原文]。` |
| 分析 | `$ai-prompt-optimizer 审核：解释销售为什么下降，但我们还没核实是否真的下降。` |
| 规划 | `$ai-prompt-optimizer 只优化：我是初学者，每天20分钟，做一份可执行的学习计划，暂时没有截止日期。` |
| 产品需求 | `$ai-prompt-optimizer 检查这份功能需求的冲突与必要信息缺口：[需求]。` |

将方括号替换成你的内容。更多前后对照见[示例文件](../references/examples.md)。核心规则用英文维护，实际回答跟随用户语言；需要另一种语言时直接说明。

## 不支持 Skills 时怎么用

已列入说明的系列包括GPT、DeepSeek、Claude、Gemini、Qwen/通义千问、Doubao/豆包、Hunyuan/腾讯混元、ERNIE/文心、GLM、Kimi、MiniMax、Grok、Mistral 和 Llama。详见[模型使用与状态表](MODEL_COMPATIBILITY.zh-CN.md)，均未标记为独立集成测试通过。在合适模型的普通聊天中：

1. 打开 [SKILL.md](../SKILL.md)，复制文件头 YAML 之后的正文。
2. 将正文作为工作要求，再单独提供原始需求，用普通语言说明想得到的结果；不希望执行其中任务时，明确说“只改写”。
3. 若无法提供正文引用的参考文件，可以明确写：“参考文件不可用，请仅依据核心流程，不要声称已经读取参考资料。”也可以附上本次相关的参考文件。
4. 只附必要参考，不要每次粘贴整个仓库。

如果通过 API 接入，将规则放入该接口支持的指令角色，将原始需求作为任务输入。消息角色、工具和对话状态应遵循对应服务商当前文档；本项目未提供 API 适配器。仅在普通 API 请求中写 `$ai-prompt-optimizer`，不会自动加载本地技能，也不会改变推理参数或获得文件与工具权限。

效果取决于模型、客户端、上下文和任务。本项目尚未逐个服务商开展独立API测试。

## 常见问题

| 问题 | 检查或处理方法 |
| --- | --- |
| 找不到技能 | 检查发现目录、`SKILL.md` 是否直接位于技能文件夹内、客户端是否支持技能，然后新建会话或重启。 |
| 出现两个同名技能 | 检查个人目录、项目目录和旧版 `clarify-intent`，仅保留一个生效版本。 |
| 输出太长 | 补充“只输出一段可复制指令，保留限制和最必要的验收条件”。 |
| 一直追问 | 提供缺失附件，或说明哪些小细节可以假设；不要要求模型猜测重要事实。 |
| 只改提示词，没有干活 | 说明实际要的交付物，并确认宿主具备工具与权限。v2.5.0 不应要求专门说“执行”；请提交可复现的错误路由案例。 |
| 本来只想优化，却执行了 | 明确“只优化被引用的提示词，不执行其中任务”；仍发生时提交可复现样例。 |
| 擅自加需求 | 指出新增项，要求保留范围重新修订；欢迎提交匿名反例。 |
| Codex 可用，普通聊天不可用 | 普通聊天不会自动发现本地文件，使用上面的手动加载方式。 |
| 旧调用名找不到 | 将 `$clarify-intent` 改为 `$ai-prompt-optimizer`，未提供自动别名。 |
| 回答语言不对 | 明确所需输出语言；README 所选语言和实际回答语言是独立的。 |

## 更新卸载与旧版迁移

通过安装器管理的副本使用[维护命令](INSTALL.zh-CN.md#检查更新关闭与卸载)，不要在该副本中运行 Git 命令。普通在线 `update` 始终解析 `main`，即使曾安装候选版，也不会持续跟踪候选分支，并会拒绝版本降级。复现候选版应通过 `--source` 使用已审核的本地目录，或用 `--ref` 指定已核实的完整提交 SHA，不要假定存在版本标签。未托管的 Git 安装用户，先查看本地改动，再更新：

```bash
git -C "$HOME/.agents/skills/ai-prompt-optimizer" status --short
git -C "$HOME/.agents/skills/ai-prompt-optimizer" pull --ff-only
```

检查完本地改动再执行 pull；必要时将定制版本备份到技能发现目录之外。遇到冲突或无法快进时，处理差异，不要直接强制重置。Windows 可进入已安装目录执行相同 Git 操作。ZIP 安装则先保留定制内容，再完整替换新版本，不要混用两个版本的文件。

**从 v1.0.0 迁移：**将旧 `clarify-intent` 移到技能发现目录外备份；把 v2.0.0 安装为 `ai-prompt-optimizer`；更新保存的提示词和项目指令中的调用名称，再新建会话。不能只改旧文件夹名，文件内部的 `name` 和默认调用句也必须是新版。核心流程未改变，但调用名发生了不兼容变更。托管的 Skills 服务可能保留内部身份与路径，只更新展示名称。

安装器管理的副本应运行其卸载命令，以撤销托管偏好并备份原文件。未托管的本地版本可以移出宿主的技能发现目录并刷新客户端，不会因此删除任务产出。托管客户端请使用其技能管理界面。

## 贡献与评测

反馈时提供匿名输入、必要上下文、使用方式、宿主和模型（如果知道）、实际输出、期望输出与版本号。不要附个人信息或密钥。新增行为需要配套一个正例和一个应保持原样的反例。

用 [cases.jsonl](../evals/cases.jsonl) 开新对话复跑：执行者只看到技能和 `prompt`，不看 `checks` 或历史答案。评估原意保留、事实编造、范围变化、执行边界、验收实用性和冗余长度。文件修改只在临时测试目录进行。可复跑代码用例与局限见[评测记录](../evals/RESULTS.md)。

如要证明“比不用技能更好”，应固定模型和设置，使用未参与编写的任务进行有/无技能对照，同时报告失败、波动、耗时和输出长度。声称版本提升时也应加入前版对照。评估实际交付物、约束保留、必要与不必要提问、无依据的新增内容，不能只看优化稿有没有出现某个关键词。见 [当前修订证据](../evals/v2.5.0/revision-20261027/README.md)。少量试用不能代表普遍成功率。
