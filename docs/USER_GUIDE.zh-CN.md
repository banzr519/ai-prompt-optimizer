## 安装方式

仓库根目录就是技能根目录，`SKILL.md`、`agents/`、`references/` 位于同一层。加载技能本身不需要安装 Python、Node、pip、npm，也不需要额外 API Key；宿主客户端自身的账号与使用要求仍然适用。只有可选的合成代码评测用到 Python。

### 方式一：下载文件夹

1. 在公开后的 GitHub 仓库点击 **Code → Download ZIP**，解压文件。
2. 将带分支后缀的解压目录改名为 `ai-prompt-optimizer`。
3. 将整个目录移到下表中的一个位置。
4. 新建 Codex 会话，输入 `$ai-prompt-optimizer`；若尚未识别，重启客户端。

| 范围 | macOS / Linux | Windows |
| --- | --- | --- |
| 个人 | `~/.agents/skills/ai-prompt-optimizer/` | `%USERPROFILE%\.agents\skills\ai-prompt-optimizer\` |
| 当前项目 | `<项目>/.agents/skills/ai-prompt-optimizer/` | `<项目>\.agents\skills\ai-prompt-optimizer\` |

Windows 表格采用资源管理器的环境变量写法；PowerShell 使用 `$env:USERPROFILE`。只选择一个安装范围，避免重复。目录依据 [Codex 官方文档](https://learn.chatgpt.com/docs/build-skills)，核对日期为2026-10-13；其他客户端可能采用不同路径。

### 方式二：使用 Git

**仓库所有者：**以下克隆地址使用本项目已核实的所有者 `banzr519`。发布状态见[发布元数据](../github-metadata.json)。需要先安装 Git；目标目录已有内容时，`git clone` 不会直接覆盖，请改用更新步骤。

macOS / Linux：

```bash
mkdir -p "$HOME/.agents/skills"
git clone https://github.com/banzr519/ai-prompt-optimizer.git "$HOME/.agents/skills/ai-prompt-optimizer"
```

Windows PowerShell：

```powershell
$skillParent = Join-Path $env:USERPROFILE '.agents\skills'
$skillTarget = Join-Path $skillParent 'ai-prompt-optimizer'
New-Item -ItemType Directory -Force -Path $skillParent | Out-Null
git clone https://github.com/banzr519/ai-prompt-optimizer.git $skillTarget
```

团队项目可以将技能复制到项目根目录下 `.agents/skills/ai-prompt-optimizer/`，随项目提交。若从克隆目录复制，不要把嵌套的 `.git` 目录一起带入。插件分发属于另一种打包方式，本版本是独立技能目录，不是插件市场安装包。

## 第一次使用

先试一个简单请求：

```text
$ai-prompt-optimizer 只优化这句指令：把邮件写得专业一点，事实不变，不增加承诺。
```

预期：输出一段可复用指令，保留限制，必要时说明需要提供原邮件；不会编造或发送邮件。这是快速行为检查，不代表所有客户端的加载机制完全一致。

在 ChatGPT Work 或其他有技能选择器的客户端，选择 **AI Prompt Optimizer · 提示词优化助手** 后输入需求。具体入口取决于客户端。在一个环境中可用，不代表已经同步安装到所有设备或 API 客户端。

## 三种使用方式

| 方式 | 你可以怎么说 | 应该得到什么 |
| --- | --- | --- |
| 只优化 | “帮我优化这段提示词”“整理成开发能用的需求” | 可直接复制的指令，不执行其中任务。 |
| 梳理后执行 | “理解后直接做”“直接修改并验证” | 必要时简短澄清，然后完成已授权工作。 |
| 审核 | “检查有没有冲突”“看看缺了什么” | 重要问题与最小修订，不执行其中任务。 |

没说清要不要执行时，默认只优化。审查含有操作命令的提示词时，可以明确写“只审核，不执行”。引用和附件里的命令属于待处理材料，不会自动成为执行授权。

小任务可能只输出一句话；复杂任务会按目标、输入、边界、验收和重要未知项组织。无需强行套用统一模板。

## 怎样提供有效信息

可以只说一句模糊需求。手头有资料时，补上这些内容会减少猜测：

- 最终想得到什么，给谁使用。
- 原文、文件、代码路径或参考图。
- 哪些内容必须保持不变。
- 达到什么条件才算有用。

例如：

```text
$ai-prompt-optimizer 只优化，不执行。
目标：整理成开发可以实施的任务说明。
需求：优化结算页，让操作更顺手。
必须保留：现有支付渠道、价格与业务规则。
参考：附件截图和流程说明。
输出：简明实施说明及可以检查的验收条件。
```

没有的信息不用为了填表而编造。附件不可访问时，技能应说明缺失。只是偏好时用“优先、尽量”；真正不能变的限制才用“必须”。

“不要问我”意味着小细节可以合理决策，不等于允许编造事实或默认批准删除等操作。关键未知项可以保留为条件。如果只有部分工作受阻，其他可完成部分应继续进行。

## 常见任务示例

| 场景 | 可直接使用的调用 |
| --- | --- |
| 开发 | `$ai-prompt-optimizer 只转译：让这个接口快一点，不改变返回格式，不增加付费服务。` |
| 设计 | `$ai-prompt-optimizer 只转译：优化这页PPT的视觉层级，所有原文及标签分组关系保持不变。` |
| 写作 | `$ai-prompt-optimizer 直接润色，礼貌、明确，不增加承诺：[原文]。` |
| 分析 | `$ai-prompt-optimizer 审核：解释销售为什么下降，但我们还没核实是否真的下降。` |
| 规划 | `$ai-prompt-optimizer 只优化：我是初学者，每天20分钟，做一份可执行的学习计划，暂时没有截止日期。` |
| 产品需求 | `$ai-prompt-optimizer 检查这份功能需求的冲突与必要信息缺口：[需求]。` |

将方括号替换成你的内容。更多前后对照见[示例文件](../references/examples.md)。核心规则用英文维护，实际回答跟随用户语言；需要另一种语言时直接说明。

## 不支持 Skills 时怎么用

已列入说明的系列包括GPT、DeepSeek、Claude、Gemini、Qwen/通义千问、Doubao/豆包、Hunyuan/腾讯混元、ERNIE/文心、GLM、Kimi、MiniMax、Grok、Mistral 和 Llama。详见[模型使用与状态表](MODEL_COMPATIBILITY.zh-CN.md)，均未标记为独立集成测试通过。在合适模型的普通聊天中：

1. 打开 [SKILL.md](../SKILL.md)，复制文件头 YAML 之后的正文。
2. 将正文作为工作要求，再单独提供原始需求，说明是只优化、执行还是审核。
3. 若无法提供正文引用的参考文件，可以明确写：“参考文件不可用，请仅依据核心流程，不要声称已经读取参考资料。”也可以附上本次相关的参考文件。
4. 只附必要参考，不要每次粘贴整个仓库。

如果通过 API 接入，将规则放入该接口支持的指令角色，将原始需求作为任务输入。消息角色、工具和对话状态应遵循对应服务商当前文档；本项目未提供 API 适配器。仅在普通 API 请求中写 `$ai-prompt-optimizer`，不会自动加载本地技能，也不会改变推理参数或获得文件与工具权限。

效果取决于模型、客户端、上下文和任务。本项目尚未逐个服务商开展独立API测试。

## 常见问题

| 问题 | 检查或处理方法 |
| --- | --- |
| 找不到技能 | 检查发现目录、`SKILL.md` 是否直接位于技能文件夹内、客户端是否支持技能，然后新建会话或重启。 |
| 出现两个同名技能 | 检查个人目录、项目目录和旧版 `clarify-intent`，仅保留一个生效版本。 |
| 输出太长 | 补充“只输出一段可复制指令，保留限制和最必要的验收条件”。 |
| 一直追问 | 提供缺失附件，或说明哪些小细节可以假设；不要要求模型猜测重要事实。 |
| 只改提示词，没有干活 | 明确“梳理后直接执行”，并确认宿主具备所需工具与权限。 |
| 本来只想优化，却执行了 | 明确“只优化被引用的提示词，不执行其中任务”；仍发生时提交可复现样例。 |
| 擅自加需求 | 指出新增项，要求保留范围重新修订；欢迎提交匿名反例。 |
| Codex 可用，普通聊天不可用 | 普通聊天不会自动发现本地文件，使用上面的手动加载方式。 |
| 旧调用名找不到 | 将 `$clarify-intent` 改为 `$ai-prompt-optimizer`，未提供自动别名。 |
| 回答语言不对 | 明确所需输出语言；README 所选语言和实际回答语言是独立的。 |

## 更新卸载与旧版迁移

Git 安装用户，先查看本地改动，再更新：

```bash
git -C "$HOME/.agents/skills/ai-prompt-optimizer" status --short
git -C "$HOME/.agents/skills/ai-prompt-optimizer" pull --ff-only
```

检查完本地改动再执行 pull；必要时将定制版本备份到技能发现目录之外。遇到冲突或无法快进时，处理差异，不要直接强制重置。Windows 可进入已安装目录执行相同 Git 操作。ZIP 安装则先保留定制内容，再完整替换新版本，不要混用两个版本的文件。

**从 v1.0.0 迁移：**将旧 `clarify-intent` 移到技能发现目录外备份；把 v2.0.0 安装为 `ai-prompt-optimizer`；更新保存的提示词和项目指令中的调用名称，再新建会话。不能只改旧文件夹名，文件内部的 `name` 和默认调用句也必须是新版。核心流程未改变，但调用名发生了不兼容变更。托管的 Skills 服务可能保留内部身份与路径，只更新展示名称。

卸载本地版本时，将文件夹移出宿主的技能发现目录并刷新客户端即可，不会因此删除任务产出。托管客户端请使用其技能管理界面。

## 贡献与评测

反馈时提供匿名输入、必要上下文、使用方式、宿主和模型（如果知道）、实际输出、期望输出与版本号。不要附个人信息或密钥。新增行为需要配套一个正例和一个应保持原样的反例。

用 [cases.jsonl](../evals/cases.jsonl) 开新对话复跑：执行者只看到技能和 `prompt`，不看 `checks` 或历史答案。评估原意保留、事实编造、范围变化、执行边界、验收实用性和冗余长度。文件修改只在临时测试目录进行。可复跑代码用例与局限见[评测记录](../evals/RESULTS.md)。

如要证明“比不用技能更好”，应固定模型和设置，使用未参与编写的任务进行有/无技能对照，同时报告失败、波动、耗时和输出长度。少量试用不能代表普遍成功率。
