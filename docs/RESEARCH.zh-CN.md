# 开源项目研究与 v2.2.0 改进决策

[English](RESEARCH.md) | **简体中文** · [返回首页](../README.zh-CN.md)

研究日期：2026-10-14。研究范围是下列项目的官方仓库 README、关联的一手文档及其描述的工作流程；没有本地部署这些项目，没有进行完整代码审计，也没有复现其性能宣传。选择依据是与当前需求的相关性、明确的使用流程和可核查的评测机制，而非仅看 Stars。这不是穷尽排名。

## 结论

AI Prompt Optimizer 继续提供可在现有 AI 客户端中调用的轻量技能。保留“模糊需求 → 明确指令”的入口，增加“失败反馈 → 局部修订 → 有证据地检查”的流程。新手仍然只需一句话，进阶用户可要求模板、输出格式、交接和比较。

## v2.2.0 已实现的改进

1. **按失败结果修提示词。** 保留有效部分，区分观察到的问题与猜测；支持只给修改行。不再用“补得更长”作为默认办法。
2. **复用变量。** 保留原变量名与分隔符；说明必填/可选、缺失处理以及 false、0、空值的区别。适合客服、商品介绍、报告等重复工作。
3. **明确输出格式。** 保留 JSON 字段、枚举、类型和空值规则；普通聊天与 API 角色分开处理。不声称提示词能保证 JSON 永远正确。
4. **有依据地比较。** 只有提示词时给静态审阅；有实际回答时比较观察；明确要求运行且工具可用时才做有边界的测试。允许结论为“尚无法判断”。
5. **长对话交接。** 保留最新确认需求及未被取消的限制，把废弃方案移出当前指令，指出必须随附的材料。
6. **图像/视频需求。** 保护构图、尺寸、字幕、角色与参考图约束；遇到缺图说明缺失，不假装看过。不默认生成媒体或编造模型参数。
7. **按任务控制长度。** 小任务一段话；复杂任务结构化；用户可要求精简、详细、只输出结果。全部通过自然语言调用，不要求背新命令。

核心入口仍为 `$ai-prompt-optimizer`，原来的只优化、执行、审核三种方式不变。新增流程只在相关任务中读取，不把全部资料塞进每次上下文。

## 后续优先级与进入条件

| 优先级 | 候选工作 | 进入条件与可验收结果 |
| --- | --- | --- |
| 下一步 | 可选的 promptfoo 评测示例或连接器 | 用户确实需要批量评测；固定版本、明确凭据与调用预算；同一输入比较原版与候选，导出真实结果 |
| 下一步 | 社区失败案例与回归集 | 获得匿名且允许分享的样例；每项包含上下文、实际结果、期望与一个不应改写的反例 |
| 有需求再做 | 可保存、回滚的模板资产 | 明确客户端存储方式、私有数据边界和同步需求；未授权时不自动修改用户的常驻指令 |
| 有需求再做 | 客户端安装包与适配层 | 分别在目标宿主实际安装和验证，报告具体版本，不能把支持某模型等同于宿主加载成功 |
| 暂不进入核心 | 自动多模型搜索、桌面/Web 完整应用 | 有稳定用户需求、成本预算和维护能力后单独立项；保持纯指令技能可独立使用 |

## 验收原则

- **行为正确：** 不丢限制、不编造事实、不把只改提示词变成实际执行；明确请求执行时继续完成。
- **体验可用：** 变量可复用，说明不超过所需复杂度，输出能独立复制。
- **效果可信：** 静态检查、代理试用、下游任务效果、跨模型 API 基准是不同证据，分别记录。
- **停止条件明确：** 达到任务标准或预算即交付；没有数据不编造分数、提效比例或 token 节省。
