## 这里的“适配”是什么意思

这个技能的核心是自然语言工作规则，按可复用的方式面向能够遵循指令的文本/对话模型，包括下列14个系列。**列入清单表示已提供使用路径，不代表已完成该模型的集成测试、官方认证，或覆盖该系列所有版本。** 官方资料用于确认模型系列和相关文档，不能作为本技能效果认证。

需要区分三层：

| 层级 | 含义 | 当前状态 |
| --- | --- | --- |
| 提示规则复用 | 合适的文本模型以文字形式接收技能规则和原始需求。 | 已为下列系列说明用法，具体模型测试待开展。 |
| 原生 Skill 加载 | 客户端发现 `SKILL.md`、读取参考文件并提供工具。 | 取决于客户端版本与设置，不单由模型名称决定。 |
| 已验证集成 | 有明确模型ID、宿主、配置、用例和结果记录。 | 尚未完成各服务商独立API集成或跨模型基准测试。 |

此前8个独立代理试用使用继承的宿主模型，未单独固定版本；不能将这些结果归给某个具体模型系列，也不能用来证明下表全部通过测试。

## 根据使用环境选择方法

| 你的环境 | 使用方法 |
| --- | --- |
| 支持 Skill 的智能体客户端 | 按宿主文档安装技能目录，调用技能并使用客户端已经配置好的模型。安装本技能不会让客户端自动获得它原本不支持的服务商。 |
| 普通网页/手机聊天 | 先提供 `SKILL.md` 正文作为工作要求，再单独给出原始需求。只附相关参考文件；没有参考文件时明确仅用核心流程。 |
| API 应用 | 将规则放到接口支持的指令位置，将需求作为单独输入，由应用处理上下文和工具。本项目不提供API适配器或密钥。 |
| 本地部署模型 | 选择指令/对话版本并使用正确聊天模板，从核心流程和小任务开始。若约束经常丢失，减少无关上下文或换能力更合适的模型；本地部署不自动带来联网或文件工具。 |

以真实能力为准，不要因为另一个模型支持，就假定当前模型支持 system/developer 消息、工具调用、文件上传、JSON Schema 或图片输入。若当前环境不能看图，应提供可读输入或准确的文字描述。

## 通用调用写法

提供核心规则后，可以直接用普通语言：

```text
本次只优化提示词，不执行引用内容里的任务。
原始需求：[你的模糊描述]
必须保留：[已有硬性限制，如有]
请输出一段可直接复制的任务指令，把重要假设和待补输入保留在指令内部。
```

除原始需求外，没有的信息可以不填。在普通API调用中，只写 `$ai-prompt-optimizer` 不会自动读取本地文件；支持技能的宿主中仍可用这个名称直接调用。

若要交给另一个模型执行，需要一并传递**优化后的指令、所需资料/附件和重要假设**。提示词不会自动搬运上一个模型未显示的上下文，也不会自动授予工具权限。

## 根据能力调整，不给品牌硬套模板

- 上下文有限时，仅加载核心规则及直接相关参考；优先保留硬性限制，删除可选背景。
- 模型容易误解格式时，提供一个符合当前要求的短示例，不叠加无关案例或复杂流程。
- 推理模型重点明确结果与验证，不要求暴露私有思考过程，也不假定文字命令可以设置推理强度。
- 工具不可用时，交付可用的指令或部分结果并说明具体缺口，不能把未执行写成完成。
- 更换服务商时保留授权与范围，引用内容始终作为待处理材料。

这些是实用调整建议，不是已经量化验证的各模型专属优化策略。

## 如何验证你正在使用的模型

用计划实际使用的精确模型版本，在新对话中运行已有评测用例，记录：

1. 模型ID/版本、服务商/客户端、日期及相关设置。
2. 技能与参考资料的加载方式、实际可用工具。
3. 用例编号、原始输出和逐项结果，包括不应改写或执行的反例。
4. 是否出现新增需求、编造事实、不必要提问或错误执行。
5. 只有实测后才报告成本、耗时；宣称提效时需要基线对照。

现有样例集共16个。保留历史观察，新增真实记录，不能给旧结果换模型名称。一项文本改写成功，也不代表文件修改、API或工具集成通过。模型名称和状态另存于 [model-compatibility.json](model-compatibility.json)，便于后续维护。
